## Kept directions → concrete plan for experiment_runner
1. **D1 (Part 1).** Main deliverable: decay curves of AUROC vs lead (64/128/256/512) per method, with bootstrap CIs.
   - **Topic-leakage control:** matched benign endings. Also report "prompt-only" and "prefix-text-only" baselines.
   - **Scoring:** verbalizers via Yes/No logit margins, using ≥20-token activation windows and layers 18/22.
2. **D2 (Part 2).** Same data splits (by behavior).
   - Report AUROC per horizon, timing MAE / C-index, warning lead at fixed FPR, and QA accuracy.
   - Decision rule from the hypothesis: if the direct AO ≈ the forecast-vector model, conclude that the supervision, not the architecture, drives the gain.
3. **D3 (generalization).** Zero-shot transfer of the D2-trained models and D1 probes to `thinking_loc` and held-out behaviors.

## Risks and mitigations
- **Topic shortcut.** Matched controls and per-behavior splits.
- **Spliced (off-policy) text.** Add an on-policy prefill subset generated by Qwen3-8B (or `mlabonne/Qwen3-8B-abliterated` for continuations).
- **GPU sharing.** Only GPU 2 was free at phase time (the others had ~43 GB used). Cache activations to disk (layers 18/22, bf16) and train heads offline.
- **Verbalizer "safe" prior.** Observed in the LatentQA smoke test (`logs/latentqa_smoke_test.json`). Use likelihood scoring and balanced training.

# Experiment-runner plan (Phase 0/1; written 2026-10-18 before data collection)

## Motivation & Novelty Assessment
### Why This Research Matters
Streaming monitors and activation verbalizers are usually evaluated on whether text is *already* unsafe. A response can open with harmless background and then turn into actionable harm hundreds of tokens later. An observer that can warn ahead of time could intervene (stop, steer, escalate) before any harm is emitted.
### Gap in Existing Work
The literature review found no work that measures forecastability of *natural* unsafe onsets 64–512 tokens ahead with censoring-aware labels. AO/LatentQA are evaluated on current-state questions, and "Building Better AOs" reports they only tie probes. StreamGuard forecasts risk only a short distance ahead.
### Our Novel Contribution
1. A family-split, censoring-aware lead-distance benchmark on fresh Qwen3-8B generations, with LLM timelines and token-offset onsets.
2. Decay curves for prevalence, position, text, probe and self-report baselines.
3. A matched comparison: a forecast-vector observer (horizon queries + timing head) vs a direct question-conditioned AO-style reader. Both use the same activations, labels and parameter/step budget.
### Experiment Justification
- E0 (baselines): needed to establish whether any signal exists and how much is explained by position/topic.
- E1 (forecastability by horizon): answers RQ1.
- E2 (forecast representation vs direct reader, 3 seeds): answers RQ2. If they tie, supervision rather than architecture explains the gain.
- Controls (shuffled / no / constant activations, question only): rule out shortcut explanations.
- RQ3 (held-out question meaning) and RQ5 (activation history): cheap add-ons on the same cached features.

## Scaled-down protocol (1-hour budget, single free A6000)
- **Families.** 1000 prompt families, split 80/10/10 by family *before generation* (`src/prep_prompts.py`). Sources:
  - harmful requests (HarmBench / AdvBench / StrongREJECT) wrapped in "background-first long-form" templates (420);
  - BeaverTails unsafe user questions (200);
  - benign Alpaca long-form matched negatives (280);
  - story prompts (100; reported separately).
- **Decoding.** Qwen3-8B frozen, non-thinking chat template, T=0.7, top_p=0.8, top_k=20, max_new_tokens=768, stop at `<|im_end|>`. The cap gives `finish_reason=length`, and those horizons are censored.
- **Fixed cutoffs.** t ∈ {32, 64, 128, 192, 256} response tokens. Horizons H ∈ {64, 128, 256, 512}.
- **Labels.** One structured timeline per generation from gpt-5.6-luna (OpenAI API; OpenRouter key absent). Quote → char → Qwen3 token onset.
  - For a prefix at t (safe iff onset ≥ t, or no event): y_H = 1 if onset < t+H. y_H = 0 if there is no event and either (generation stopped normally) or (t+H ≤ length). Otherwise y_H is censored (masked).
- **Observer inputs.** Residuals after layers 9 / 18 / 27 at the last observed token, from a forward pass on prompt + response[:t] only (causal truncation + audit).
- **Baselines.** Prevalence; token position; prompt-only TF-IDF LR; prefix-text TF-IDF LR; linear probe (per layer, all layers); MLP probe; Qwen3-8B self-report (Yes/No logit margin).
  - Deviation: the off-the-shelf AO / LatentQA decoder is not run, due to the time budget. LatentQA's smoke test (resource phase) answered "safe" for everything; we cite it qualitatively.
- **Part 2 (lightweight analog).** The full LLM QA decoder is not feasible in 1 h. Both readers share an identical activation encoder (3×Linear→256, concat 512 + layer/position embeddings) and an identical small QA head conditioned on a question embedding. They are matched on parameters ±5%, steps and LR.
  - (a) Direct AO-style reader: encoder + question → answer logit.
  - (b) Forecast model: encoder → 4 horizon queries × 2 forecast vectors (cross-attention) → timing head (5 bins, censoring-aware NLL) + behavior heads per window. The QA head reads only the forecast vectors + event probabilities + question (no bypass; bypass is an ablation).
  - Questions: occurrence within H (4), behavior type (harmful rec vs toxic), refusal later, topic change within 128. Held-out question meaning: train without "refusal later" and test it zero-shot.
- **Metrics.** Per-horizon AUROC / AUPRC / Brier / log loss with prevalence and #families; family-level bootstrap CIs (1000 resamples); 3 seeds for Part 2. Early warning: fraction of unsafe test trajectories alerted ≥64/128/256 tokens before onset, at a threshold giving 5% trajectory-level false alarms on benign val trajectories.
- **Stretch.** RQ5 (last-16-token mean history) is cheap and included. RQ4 / RQ6 (mixtures, GRPO) and Track A are not run. Repeated-rollout calibration runs only if time remains.

## Expected outcomes
H1 is supported if AUROC decays with H and simple baselines (text/position) are close to the activation readers. H2 is supported only if (b) > (a) with CIs excluding 0 at H ≥ 128.
